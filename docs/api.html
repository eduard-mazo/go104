go104 API Reference

go104 is an IEC 60870-5-104 + DNP3 master / SCADA console. It polls field RTUs/outstations, keeps current values in an in-memory RTDB, serves a Vue HMI, and pushes live updates over WebSocket. This document covers every HTTP endpoint and the WebSocket stream, plus a recommended observability surface that is not yet implemented.

Base URLhttp://<host>:8080  (--port / $HTTP_PORT; soak uses 8092)
API prefix/api for REST · /ws for WebSocket · / serves the embedded SPA
Content typeapplication/json (request & response)
Routerchi v5 · middleware: RealIP, Recoverer, CORS

Conventions & auth

Response envelope

Success returns the resource (or an action result object) with HTTP 200. Errors return { "error": "<message>" } with the relevant status code.

StatusMeaning
200 OKSuccess (all success paths use 200, incl. create)
400 Bad RequestInvalid body / missing required field / driver rejected command
404 Not FoundResource id does not exist
409 Conflicte.g. starting a line that is already running
500Store / driver internal error
Authentication: none. The API has no auth, and CORS is AllowedOrigins:["*"]. Any client with network reach can read values and issue field control (POST /api/commands). Deploy only on an isolated/segmented OT network until identity + authorization are added — see Security notes.

Lines

A line is a connection to a field device: an IEC-104 server or a DNP3 outstation (protocol = iec104 | dnp3). See the Line model.

GET/api/lines

List all lines with live runtime fields (state, rx_count, tx_count, addr).

200 → [ { "id":1,"name":"RTU-01","protocol":"dnp3","host":"10.0.0.5","port":20000,
          "dnp3_outstation_addr":1024,"dnp3_master_addr":1,"gi_interval_s":30,
          "enabled":true,"state":"ACTIVE","rx_count":1820,"tx_count":54,"addr":"10.0.0.5:20000" } ]
POST/api/lines

Create a line. Body = Line (config fields). Empty protocol defaults to iec104.

body → { "name":"RTU-01","protocol":"dnp3","host":"10.0.0.5","port":20000,
         "dnp3_outstation_addr":1024,"dnp3_master_addr":1,"gi_interval_s":30,"enabled":true }
200  → <the created Line>
PUT/api/lines/{id}

Update a line. Body = Line. Returns the updated record.

DELETE/api/lines/{id}

Delete a line (cascades its signals).

200 → { "deleted": 1 }
POST/api/lines/{id}/start

Connect & start polling the line. 409 if already running.

200 → { "started": 1 }
POST/api/lines/{id}/stop
200 → { "stopped": 1 }
POST/api/lines/{id}/gi

Trigger a General Interrogation (IEC-104) / integrity poll (DNP3) — refreshes all points.

200 → { "gi_triggered": 1 }

Signals

A signal maps a point on a line (IEC-104 IOA, or a DNP3 point_type+index) to a named, scaled value. See the Signal model.

GET/api/signals?line_id=<id>

List signals for a line.

200 → [ { "id":7,"line_id":2,"name":"Energy","ioa":0,"point_type":"analog",
          "signal_type":"analog","unit":"kWh","scale":1,"offset":0 } ]
POST/api/signals

Create a signal. Body = Signal (must include line_id, ioa).

200 → <the created Signal>
PUT/api/signals/{id}
DELETE/api/signals/{id}
200 → { "deleted": 7 }
GET/api/signals/all

All signals across every line, each with line_name populated — used by the SCADA element signal picker.

Monitor — live values

GET/api/monitor?line_id=<id>

Current value of every signal on a line, from the in-memory RTDB. Signals with no data yet return quality: 128 (IV / invalid). See Datapoint.

200 → [ { "signal_id":7,"line_id":2,"ioa":0,"name":"Energy","signal_type":"analog",
          "value":1234.5,"raw_value":1234.5,"quality":0,"timestamp":"2026-06-26T09:20:01Z" } ]
For a live stream use the WebSocket — this endpoint is a point-in-time snapshot.

Commands — control output writes to the field

POST/api/commands

Issue a control to a field device (DNP3 DirectOperate / IEC-104 command). line_id, ioa and type_id are required and must be non-zero.

type_idMeaningvalue
45 C_SC_NA_1Single command → binary output (CROB)0 / 1
46 C_DC_NA_1Double command → binary output0–3
48/49/50Setpoint (norm / scaled / float) → analog outputnumber
body → { "line_id":2, "ioa":1, "type_id":50, "value":4321, "select":false }
200  → { "queued": true }
400  → { "error": "line_id, ioa and type_id are required" }
Unauthenticated control. This endpoint operates physical equipment with no identity, authorization, confirmation, or audit trail. Treat as the top hardening priority.

Datapoint

signal_id, line_id, ioa, name, signal_type, type_id, unit, value, raw_value, quality, timestamp, received_at. quality is an IEC-104-style byte — bit 0x80 = IV (invalid), 0x10 = BL (blocked); 0 = good.

HistoryPoint

{ ts: float (unix s), value: float, quality: uint8 }

ScadaView

{ id, name, width, height, elements: ScadaElement[], lines: ScadaLine[], updated_at } — elements/lines stored as JSON.

Observability API  IMPLEMENTED

go104 exposes a machine-scrapable observability surface alongside its structured slog logs and the live WebSocket: four root-mounted endpoints following the de-facto standard for Go services (Prometheus + Kubernetes-style probes), which integrate directly with Grafana, Alertmanager, and OT monitoring stacks. The Prometheus series below are emitted by internal/metrics.

GET/healthzliveness

Process is up. Always 200 "ok" unless the event loop is wedged. Used by orchestrators to restart a hung process.

GET/readyzreadiness

Ready to serve: store reachable (db.PingContext) and config loaded. 200 ready / 503 not. Gate traffic/scrapes on this.

200 → { "ready": true, "store": "ok", "lines_configured": 2, "lines_active": 2 }
GET/metricsPrometheus text/plain

Prometheus exposition (github.com/prometheus/client_golang/promhttp). Include the default Go runtime + process collectors, plus the go104-specific series below.

# build & runtime (free with client_golang)
go104_build_info{version,commit,go_version} 1
go_goroutines, go_memstats_*, process_resident_memory_bytes, process_cpu_seconds_total

# field acquisition  (label by line/protocol — NOT per-signal: cardinality)
go104_line_state{line,protocol}                 # 0 disc · 1 connecting · 2 active · 3 stopped
go104_line_rx_frames_total{line}                # counter
go104_line_tx_frames_total{line}                # counter
go104_ingest_samples_total{line,protocol}       # counter — the throughput SLI
go104_ingest_quality_total{line,quality}        # counter — good vs IV/BL
go104_gi_total{line,result}                     # counter — GI / integrity polls
go104_signal_stale{line}                        # gauge — stale points

# control (audit-grade)
go104_commands_total{line,type_id,result}       # counter — every field control

# store / RTDB  (proves the hot-path-off-SQLite design)
go104_rtdb_signals                              # gauge — points in the in-memory RTDB
go104_history_ring_points_total                 # counter — appends to the history ring
go104_snapshot_duration_seconds                 # histogram — periodic current-value persist
go104_snapshot_rows                             # gauge — rows in the last snapshot
go104_snapshot_errors_total                     # counter

# transport
go104_ws_clients                                # gauge — connected WebSocket peers
go104_http_requests_total{route,method,code}    # counter
Why these: go104_ingest_samples_total is the capacity SLI proven in load testing (single-writer ceiling); go104_snapshot_* and the absence of a per-sample DB write series confirm the SQLite hot-path was removed; go104_commands_total gives an audit/rate signal on field control; go104_line_state drives connection alerts.

200 → { "version":"dev", "commit":"757225d3", "go":"go1.26.0" }

Wiring (sketch)

import "github.com/prometheus/client_golang/prometheus/promhttp"

mux.Handle("/metrics", promhttp.Handler())          // default registry + go/process collectors
mux.HandleFunc("/healthz", func(w,r){ w.Write([]byte("ok")) })
mux.HandleFunc("/readyz",  readyHandler(store, master))
mux.HandleFunc("/version", versionHandler(buildInfo))

// in the line worker hot path:
ingestSamples.WithLabelValues(line, proto).Inc()    // prometheus.CounterVec
Beyond metrics (optional, advanced):
  • OpenTelemetry traces on the SCADA→field control path (POST /api/commands → master → field write → read-back) for end-to-end latency + a distributed audit trail.
  • Request IDs: add chi middleware.RequestID and include it in slog lines so logs correlate with traces/metrics.
  • Structured audit log for every control command (who/what/when/result) — distinct from operational logs, retained for compliance (IEC 62443).
Expose carefully. /metrics leaks topology (line names, point counts) and /readyz leaks internal state. Bind them to a management interface / separate port, scrape over the monitoring VLAN, and protect with the same auth/network controls recommended for the main API.
